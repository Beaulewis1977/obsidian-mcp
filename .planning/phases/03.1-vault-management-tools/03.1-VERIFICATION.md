**Why human:** Requires a live Obsidian installation and actual APPDATA registry file write; cannot be verified by mocking.

### 2. WSL path cross-platform round-trip

**Test:** On a machine running WSL, call `add_vault` with a Windows-style path (e.g., `D:\MyVault`) from the WSL MCP server. Then call `list_vaults`.
**Expected:** The vault is listed with `registered_in_obsidian: true` and `exists_on_disk: true`; path normalization correctly converts between D:\ and /mnt/d/.
**Why human:** Requires a live WSL environment with a real Windows Obsidian installation; the isWSL detection and wslpath subprocess cannot be exercised in unit tests.

### 3. Config split-brain fix verification

**Test:** Start the server with a config.json at a non-default path (e.g., via CONFIG_PATH env var), then call `add_vault`. Verify the new vault entry appears in the CONFIG_PATH file, not in ~/.obsidian-mcp/config.json.
**Expected:** The vault appears only in the file pointed to by CONFIG_PATH.
**Why human:** Requires running the server with a real env var and inspecting actual file writes on disk; the getActiveConfigPath() fallback chain depends on real fs.access results.
