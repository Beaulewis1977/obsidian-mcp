## Accomplishments

- Created `src/platform/obsidian-config.ts` with full cross-platform path resolution (win32, WSL, darwin, linux) and atomic write via same-directory temp file + rename
- Added `getActiveConfigPath()` to `src/config/index.ts` — returns the first config path that exists on disk, fixing the split-brain bug where `saveConfig()` always wrote to the home directory path regardless of which config file the server loaded from
- Added three Zod schemas (`AddVaultSchema`, `RemoveVaultSchema`, `ListVaultsSchema`) following the existing `coerceBool` pattern with `.describe()` on every field
- Implemented `handleAddVault`, `handleRemoveVault`, `handleListVaults` in `src/tools/handlers-vault.ts` — all handlers hot-reload the in-memory config after writing

## Decisions Made

- Atomic write uses a temp file in the SAME directory as the target (not `os.tmpdir()`), ensuring the `rename` syscall is on the same filesystem — avoids cross-device link errors on NTFS/ext4
- `getActiveConfigPath()` iterates the same `getConfigPaths()` array as `loadConfig()` so the two functions are always in sync
- WSL username derived from `os.homedir().split('/').pop()` — avoids any env var dependency, works with any WSL distro
- `handleRemoveVault` guards: must have `confirm: true`, vault must exist, config must have >1 vault, vault must not be the default — all return `createErrorResponse()` (never throw)
- `handleListVaults` uses `Promise.all` over vault array for parallel disk access and note counting
