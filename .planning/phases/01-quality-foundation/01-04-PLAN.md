<!-- The pattern for adding structuredContent — from SDK 1.27.1 research -->

The pattern is: extract the payload object into a named variable, use it in BOTH content[0].text and structuredContent.

BEFORE (current pattern in all handlers):
```typescript
return {
  content: [{
    type: 'text',
    text: JSON.stringify({
      success: true,
      path: notePath,
      // ... more fields
    }, null, 2)
  }]
};
```

AFTER (add structuredContent):
```typescript
const payload = {
  success: true,
  path: notePath,
  // ... same fields
};
return {
  content: [{
    type: 'text',
    text: JSON.stringify(payload, null, 2)
  }],
  structuredContent: payload as Record<string, unknown>
};
```

IMPORTANT rules:
1. Do NOT add structuredContent to error returns (createErrorResponse calls). Error responses set isError: true, which causes the SDK to skip outputSchema validation per PR #655. Leave error returns unchanged.
2. The structuredContent object should be the SAME object reference as what goes into text (DRY — extract to variable, reference twice).
3. For handlers where the payload includes a spread (`...note`), the structuredContent should be the full merged object, same as what's JSON.stringified.
4. **Shape conformance:** The fields in `structuredContent` MUST match the keys declared in the `outputSchema` for that tool (set in Plan 03). For example, `get_daily_note` outputSchema requires a `path` property — confirm `payload.path` is always set in both success branches. `create_note` outputSchema requires `path` — confirm it is not omitted. If you discover any branch where a required outputSchema key is absent from the payload, add it.
