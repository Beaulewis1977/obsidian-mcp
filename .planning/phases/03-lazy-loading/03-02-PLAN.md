  <name>Task 1: Update src/index.ts — listChanged capability, lazy_loading config, oninitialized hook</name>

  <action>
Modify `src/index.ts` with three targeted changes. Do NOT restructure the file — keep the same overall flow.

**Change 1: Update Server capabilities**

Find the Server constructor (around line 49):
```typescript
capabilities: {
  tools: {},
},
```
Change to:
```typescript
capabilities: {
  tools: { listChanged: true },
},
```

This tells MCP clients the server emits `notifications/tools/list_changed`.

**Change 2: Pass lazyLoading flag and server to buildRegistry()**

The current code (around line 46) is:
```typescript
const registry = buildRegistry();
```

The problem: `buildRegistry()` needs the `server` reference, but `server` is created AFTER registry. Restructure the order:

1. Create the server FIRST (move the `new Server(...)` block above the `buildRegistry()` call)
2. Compute lazyLoading: `const lazyLoading = config.lazy_loading !== false;` (default true when undefined)
3. Call: `const registry = buildRegistry(lazyLoading, server);`

So the sequence becomes:
```typescript
// Create MCP server (moved above registry build so server ref is available)
const server = new Server(
  { name: 'obsidian-mcp-server', version: '1.0.0' },
  { capabilities: { tools: { listChanged: true } } }
);

// Build tool registry — lazy_loading defaults to true
const lazyLoading = config.lazy_loading !== false;
const registry = buildRegistry(lazyLoading, server);
```

**Change 3: Add oninitialized hook for session reset**

After the `buildRegistry()` call and BEFORE the `server.setRequestHandler` calls, add:

```typescript
// Reset enabled tools on client reconnect (session state is process-global)
server.oninitialized = () => {
  if (lazyLoading) {
    registry.resetToAlwaysLoaded();
  }
};
```

This ensures that when a client reconnects, the enabled set resets to only meta-tools (preventing stale session state from Pitfall 4 in RESEARCH.md).

**Change 4: Update the buildRegistry comment**

Change the inline comment from `// Build tool registry — registers and enables all 17 tools` to `// Build tool registry — lazy_loading defaults to true (only meta-tools enabled at start)`

**Do NOT change:**
- The ListToolsRequestSchema handler (it already uses `registry.getEnabledDefinitions()` which is correct)
- The CallToolRequestSchema handler (it already uses `registry.dispatch()` which is correct)
- The rate limiting logic
- The vault watcher logic
- The SIGINT/SIGTERM handlers

- `it('filters tools by category')` — Call with `{ category: 'Core CRUD' }`, verify only Core CRUD tools in results.
- `it('returns sorted list of all categories')` — Verify `payload.categories` is a sorted array containing at least 'Core CRUD', 'Graph', 'Meta', 'Navigation', 'Notes', 'Vault'.
